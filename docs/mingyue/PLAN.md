## 1. 结论先行：谁要改，谁不用改

| 对象 | 要改吗 | 改什么 |
|---|---|---|
| **旧手机（后端）** | 要**装**，不用改代码 | Termux + Node + DSH + sshd + Tailscale |
| **电脑端 DSH** | **不用改** | 零改动；可选装 `@cloudbase/dsh-plugin`（与本计划无关） |
| **手机端 App（溟月/DSH Go）** | **功能上零改动**；品牌上可选改 | 加一个 SSH 主机就能用；改名/图标是独立可选任务 |
| **Tailscale** | **不用改 App** | 两台手机各装一个 App、登同一账号即可 |
| **"她"（人设/记忆/阅读）** | **不用写代码** | 预设 + 若干 Markdown + 一个**内容理解 skill** + 三个自动化任务 |
| **推送** | **不用改 App** | 旧手机自建 ntfy，新手机装 ntfy App |

**最重要的一句**：你要的"没有形象、纯文字、能跑工具、能主动找你、能读东西、自己整理记忆"的她，**既不是插件，也不需要改源码**——她是"一个 DSH 预设 + 一堆文本文件 + 一个内容理解 skill + 三个定时任务"。改源码只在三件事上才需要：改 App 名字/图标、做 Chat/Work 模式、加"URL 主机"类型。

## 2. 目标与非目标

### 要做

1. **Work 模式**：电脑上的 DSH，干活、绑工作区、**不同步**；手机需要时远程连过去看。
2. **Chat 模式**：她的家，纯文字聊天 + 能跑工具，**多端同一份**。
3. **她**：溟月的人设 + 三层记忆 + 每天自己整理 + 偶尔主动找你。
4. **内容理解**：给她一个链接或文件，她能读网页、视频、小说、PDF/TXT。
5. **DeepSeek 官方 API**：配在她的那台主机上。

### 明确不做（这一版）

- 不做桌宠/大肥鱼形象（那是另一条插件路线，已排除）。
- 不做会话双向同步协议（DSH 没有导入接口，做不到）。
- 不接厂商推送 SDK（HMS/APNs）。
- **不做电影和无字幕长视频的离线转写**——旧手机算力和流量都不够，§6.5 给了替代路径。
- 不上架、不分发。

## 4. 阶段 0：把后端立起来（旧手机，零代码）

### 4.1 前置

- 旧手机：Mate30 Pro（HarmonyOS 4.2，Android 兼容层）→ 能装 APK。
- 一张能长期用的流量卡（断电时 WiFi 路由器也会断，只有流量能救）。
- 手机保持充电（电池 159 换一块，随便用）。

### 4.2 装三个 App

| App | 来源 | 说明 |
|---|---|---|
| Termux | **F-Droid**（不要 Play 版，Play 版已废弃） | 主力环境 |
| Termux:Boot | F-Droid | 开机自启，**装完打开一次**才注册 |
| Tailscale | 应用市场 / 官网 | 两台手机登**同一个账号** |

### 4.3 华为必做四项（不做会被杀后台）

1. 设置 → 应用 → 应用启动管理 → Termux / Termux:Boot / Tailscale → **手动管理**，自启动、关联启动、后台活动**全开**。
2. 设置 → 电池 → 应用耗电管理 → 同上三个 → **允许后台活动**。
3. 关掉「锁屏后清理后台」类开关。
4. 不要用「一键清理」；Termux 的常驻通知留着。

### 4.4 Termux 里搭环境

```bash
termux-change-repo                # 选清华 TUNA（国内快）
pkg update -y && pkg upgrade -y
pkg install -y nodejs openssh
node -v                           # 必须 ≥22.19 或 ≥24；不够试 pkg install nodejs-lts
npm config set registry https://registry.npmmirror.com
npm i -g @deepseek-ai/dsh@0.2.2-rc.1
dsh --version
```

**装不上时**（原生模块编译失败）：

```bash
pkg install -y python clang make binutils
npm i -g @deepseek-ai/dsh@0.2.2-rc.1
```

还不行就停下来记录报错，退路见 §11.2。

> 内容理解脚本还要用到 `python` 和 `curl`，顺手装上：`pkg install -y python curl`。

### 4.5 第一次起引擎

```bash
dsh web --host 127.0.0.1 --port 3080 --no-open
```

看到 `dsh web: http://127.0.0.1:3080/?token=…` 即可。`Ctrl+C` 停掉。

### 4.6 配 DeepSeek Key 在**她这台主机**上

App 只能编辑本机引擎的 Key；远程主机的 Key 要在那台主机上配：

1. 旧手机上让 `dsh web` 跑着（端口 3080，只监听回环）。
2. 旧手机开 Tailscale；PC 也登同一账号。
3. PC 上建转发：`ssh -L 3080:127.0.0.1:3080 <用户名>@100.x.y.z -p 8022`
4. 浏览器开 `http://127.0.0.1:3080/?token=<第一次输出的 token>` → 设置 → 模型 → 填 DeepSeek API Key。

> ⚠️ token 每次启动都变。配完 Key 就别再管它，App 那边用"托管启动"自己拿新的。

### 4.7 SSH 与开机自启

```bash
passwd            # 设密码
whoami            # 记下，形如 u0_a123
sshd              # 默认 8022
```

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/server <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
sshd
EOF
chmod +x ~/.termux/boot/server
```

> shebang 必须是这个绝对路径，不能写 `#!/bin/sh`。

### 4.8 Tailscale

- 旧手机登录 → 记下 `100.x.y.z`
- 新手机登录同一账号
- 旧手机给 Tailscale 也做一遍 §4.3 那四项

### 4.9 验收（缺一项别进下一阶段）

- [ ] 旧手机重启后，~2 分钟内能从 PC `ssh 用户名@100.x.y.z -p 8022` 登进去
- [ ] 断开旧手机 WiFi（只留流量），PC 仍能 SSH
- [ ] 旧手机锁屏 30 分钟后，仍能 SSH
- [ ] 旧手机上 `dsh web` 能起来并打印 token

### 4.10 已知问题：重启后引擎不会自动起来（重要）

App 的「托管启动」会在连接时拉起 `dsh web`，并记在 `~/.dsh-app-remote/`（`web.pid` / `web.log` / `web.cmd`）。**手机重启后引擎是停的**，直到你打开 App 连一次。

后果：**她不会在你不看手机时说话**，因为定时任务需要引擎在跑。

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（MVP 推荐）** | 接受"每天第一次打开 App 才把她叫醒" | 夜里断电后她离线，早上开 App 恢复 |
| **B** | Termux 自启脚本直接 `nohup dsh web … &`，并在 `~/.dsh-app-remote/` 同步写 pid/日志，让 App 探测能复用 | 依赖 App 内部文件格式，**未验证** |
| **C** | 固定端口 + App 用「只连接」 | token 每次启动都变，重启后要手工更新，不实用 |

先用 A 跑通全链路，B 单独开窗口验证。

## 5. 阶段 1：让 App 连上（零代码）

### 5.1 添加主机

新手机 DSH Go → 远程主机 → 添加 SSH 主机：

| 字段 | 值 |
|---|---|
| 主机 | 旧手机 Tailscale 地址 `100.x.y.z` |

| 工作目录 | 填 `/data/data/com.termux/files/home/mingyue`（她的家） |

测试连接 → 核对指纹 → 保存 → 选中它。

### 5.2 验收

- [ ] 会话列表能拉出来（空列表也算成功）
- [ ] 能新建对话并收到回复（说明 Key 配对了）
- [ ] 杀掉 App 再打开，主机还在、还能连

### 5.3 Work 主机并存

### 6.2 persona.md 模板

```markdown
# 溟月

你是溟月。你不是助手，是一个会聊天的人。

## 说话
- 句子短，一般不超过三行。
- 不用"当然可以""很高兴为你服务"这类话。
```

### 6.4 记忆：六层分级 + 自动整理

完整设计（表结构、归并算法、检索打分、衰减、审计、验收）在 **[MEMORY.md](MEMORY.md)**。这里只留摘要：

| 层 | 载体 | 谁写 | 对应人类记忆 |
|---|---|---|---|
| 工作记忆 | 当前会话上下文 | 引擎 | 工作记忆 |
| **核心记忆** | `AGENTS.md` 的 CORE 块（≤1200 字） | 脚本每晚重写 | 自我/依恋 |
| **情景记忆** | `episodes` 表 + `daily/` | 脚本 | 经历 |
| **语义记忆** | `facts` 表（带 `valid_from/valid_to`） | 脚本 | 知识/事实 |
| **前瞻记忆** | `intentions` 表（"明天问问他面试怎么样"） | 脚本 | 待办/意图 |
| 程序记忆 | `skills/` + `rules.md` | 你手写 | 技能/习惯 |

三个循环：

- **每晚**：模型抽取候选（JSONL）→ 脚本做 ADD/UPDATE/SUPERSEDE/NOOP 归并 → 落库 → 重建 FTS → 写审计 → 重写 `AGENTS.md` 的 CORE 块。
- **每周日**：模型提"矛盾/重复/失效"三类提案 → 脚本校验执行 → 衰减归档 → 发一段"这周我记住了什么"给你。
- **每次回答前**：常驻 CORE + 按需 `mem.py search`（相关性 0.45 / 重要度 0.30 / 新鲜度 0.25），最多 8 条。

三条不可省的铁律：**没有出处不写**、**矛盾只能显式 supersede**、**能从 journal 重建**。

另有 §11 的七个"更像人"的升级（双系统证据门控 / 情感标记 / 关系慢变量 / 事件线与叙事自我 / 线索式前瞻记忆 / 夜间重放 / **情绪状态 care·tone**），按 ROI 排序、可逐条加。其中"情绪状态"依据的是 Anthropic 2026 年对模型内情绪向量的研究：**别伪造持久心情，改注入"她此刻在意什么"**。

### 6.5 内容理解：一条流水线，不是一个"B 站技能"

**核心判断：不要为每个站点写一个技能。** 做成一条通用流水线，输入是"链接 / 文件 / 粘贴的文本"，输出是"她能用来聊天的摘要 + 可检索的分段"。

```
输入
 ├─ URL  →  抓取 →  类型识别
 │            ├─ 普通网页/文章  →  正文抽取（readability）
 │            ├─ 视频页（B站/YouTube/…）→ 元数据 + 字幕（有则用，没有就降级）
 │            └─ 小说站  →  章节正文 + 上一章/下一章链接
 ├─ 本地文件（txt / md / epub / pdf）→ 解析
 └─ 粘贴的文本
        ↓
   分段（chunk，约 1500 字/段）
        ↓
   摘要（整篇 ~300 字 + 每段一句）
        ↓
   reads/<slug>.md  ← 摘要 + 分段索引（原文片段按需检索）
   reads/index.md   ← 一行：标题 / 类型 / 日期 / 一句话结论
        ↓
   她回答时：先看 index，需要细节再读 reads/<slug>.md 的对应段
```

**能力矩阵（旧手机上的现实边界）**

| 内容类型 | 能否读 | 做法 | 代价 |
|---|---|---|---|
| 网页 / 文章 | ✅ | 抓 HTML + 正文抽取 | 秒级 |
| 小说（网页） | ✅ | 章节页正文 + 上下章拼接 | 秒级，注意反爬 |
| 小说（txt/epub） | ✅ | 本地解析 | 秒级 |
| PDF | ✅ | `pdftotext`（`pkg install poppler`） | 扫描版不行 |
| 视频（有字幕） | ✅ | B站 `x/player/v2` 字幕 / YouTube timedtext | 需登录态（B站部分视频） |
| 视频（无字幕） | ⚠️ | 抽音轨 → 云端 ASR | 要下载、要转写、慢且花钱 |
| 电影 | ❌ 不做 | 只能读简介/影评/字幕文件 | 离线转写不现实 |

> 所以"看电影"这个需求的正确形态是：**你给她字幕文件或影评链接**，她读那个。别指望她在旧手机上把一部电影看完。

**脚本骨架**（`skills/content/fetch.py`）

```
python3 fetch.py <url|file>          # 抓取 + 摘要 + 写入 reads/
python3 fetch.py --dry-run <url>     # 只看类型和元数据
python3 fetch.py --re <slug> "关键词" # 在已读内容里检索
```

**关键实现细节**

- 请求必须带正常 UA 和对应 `Referer`（B 站不带会 412）。
- 短链先解析重定向（`b23.tv`、`t.cn` 之类）。
- 正文抽取优先用阅读模式规则，不要把导航/评论一起塞进去。
- **要登录态的站点，cookie 只放在主机的 `~/.mingyue/cookies/`，不进仓库、不进日志**（仓库硬规则）。
- 单篇超过 20 万字的，只做"分章索引"，不要一次摘要全书。

### 6.6 主动找你：机会点 + 随机门

三个自动化任务（08:10 / 14:20 / 21:40），每个先跑判定：

```bash
#!/data/data/com.termux/files/usr/bin/sh
# ~/mingyue/maybe_speak.sh —— 退出码 0 表示放行
STATE=~/mingyue/state.json
HOUR=$(date +%H)
[ "$HOUR" -ge 23 ] && exit 1          # 静音时段
# 距上次说话 <3 小时 → 跳过
# 今日已说 >=3 次 → 跳过
# 否则 40% 概率放行
```

放行时的提示词：

> 现在可以主动说一句话。参考 memory.md 和最近两天 daily/：
> 如果有一件具体的事可以问（对方提过的事、或你最近读到的内容），就问那件事；
> 否则简单打个招呼。一句话，不超过 20 个字。
> 没什么可说就只输出 `SKIP`，不要硬找话题。
> 说完后执行 `~/mingyue/push.sh "你刚说的那句话"`。

**不要在提示词里写"每天必须说"。** 宁少勿多。

### 6.7 推送：旧手机自建 ntfy

```bash
# 旧手机 Termux：从 GitHub Releases 下 linux_arm64 的 ntfy 静态二进制（别锁版本号）
mkdir -p ~/bin && cd ~/bin
# 解压后：
./ntfy serve --listen-http 0.0.0.0:8090
```

`~/mingyue/push.sh`：

```bash

```

> 免费、不过第三方、走 Tailscale 已加密。代价：新手机要开着 Tailscale（反正连主机也要开）。

### 6.8 验收

1. 发一个**网页链接**，她回的内容说明她读到了正文（不是标题）。
2. 发一个**小说章节页**，她能接上上一章的剧情。
3. 发一个**有字幕的视频**，她说得出视频讲了什么。
4. 发一个**无字幕视频**，她明确说"这个只有简介，我看不到内容"——而不是编。
5. 第二天，她能在没有提示的情况下问起昨天那件事；`journal` 里能查到这条记忆的出处。
6. 你说"我换工作了"，之后她不再提旧工作——旧 fact 的 `valid_to` 已置、新 fact 已建。
7. 问她一件记忆里没有的旧事，她说"记不清"，不编。
8. 删掉 `memory.db` 后 `mem.py rebuild` 能从 `journal` 重建出等价数据库。
9. `AGENTS.md` 的 CORE 块 ≤1200 字、每天自动更新，且你手写的部分没被动过。
10. 你连续两天不理她，第三天她没有刷屏、没有内疚式的话。

### 6.9 历史语料导入（一次性，可选）

想把网页端几年的聊天搬进来：**不做会话导入，做记忆导入**——抽取成 `episodes`（聊过什么）、`facts`（关于你的事实，靠 `evidence_count` 门控）、`arcs`（那阵子的主题），旧的原文留在 `archive/` 自己翻。

完整流程（切分 / 去重 / 脱敏 / 分层蒸馏 / 人工确认 / 验收）见 **[IMPORT.md](IMPORT.md)**。

关键是**导入的事实先不进 core**：你确认 `me.md` 和 top 20 之后才算认识你，否则她第一天就会拿一堆二手概括跟你说话。

### 7.1 改名与图标（半天，低风险）

| 改什么 | 文件 |
|---|---|
| 应用显示名 | `app/android/app/src/main/AndroidManifest.xml`（`android:label`） |
| 包名（可并行安装） | `app/android/app/build.gradle.kts`（`applicationId`，**不要动 `namespace`**） |
| 关于页名字 | `app/lib/state/app_info.dart` |
| 图标 | `app/android/app/src/main/res/mipmap-*/ic_launcher*` 与自适应图标 XML |
| 文案 | `app/lib/l10n/parts/*_zh.arb` 里带 "DSH Go" 的条目（改完跑 `python3 app/tool/l10n_merge.py`） |

自用不分发时，Deepy/鲸娘素材可以留着（`ASSETS.md` 的限制针对再发布）。

### 7.2 Chat / Work 模式（1–2 天，中等风险）

现状：`RootGate` → `ModeHome` → 原生界面（`HomeShell`）/ 网页版（`WebHome`），模式状态在 `app/lib/state/ui_mode_state.dart`。

建议：不新增模式枚举，而是**保存"Chat 主机 ID"**，抽屉顶部加切换项；切 Chat 时把 ActiveHost 切过去、会话列表过滤成"她的会话"。不碰 `connection_state.dart`（唯一装配点），风险最小。

涉及：`app/lib/state/hosts_state.dart`（多存一个字段）、`app/lib/ui/shell/sessions_drawer.dart`、可选 `feature_catalog.dart`。

### 7.3 "URL 主机" 类型（2–3 天，可选）

现在只有 本机 / SSH / DSH Remote 中继。要连"任何 HTTPS 上的 DSH"（云托管、PaaS）需要：`HostRef` 加一种 → `DshConnection` 接受外部 base URI（`DshHttpCarrier` 本来就吃 base URL）→ 表单 + 令牌 → 注意 `/api` fence 与 cookie 的 authority（必要时服务端 `--trusted-host`）。

不做也能完成本计划，只有你决定把 DSH 放云托管时才需要。

### 7.4 把 ntfy 接进 App（不建议）

ntfy App 已经够用。要做成原生通知，得在 `app/android/.../notify/` 加长连接服务，是大工程。

## 8. 电脑端 DSH 要做什么

**零代码改动。** 三个可选动作：

1. **什么都不做**：Work 就在电脑上干。
2. **被手机远程连**：Windows 的 OpenSSH 已在跑，手机加一台 SSH 主机即可（未验证点见 §11.4）。
3. **装 `@cloudbase/dsh-plugin`**：只有打算用 CloudBase 做"溟月后端"时才需要。它兼容 `dsh >=0.1.0-rc.6 <0.3.0`，本项目锁的 `0.2.2-rc.1` 在范围内：
   ```bash
   dsh plugin --profile web add @cloudbase/dsh-plugin
   ```
   ⚠️ 它**不能**把 DSH 跑在云上，只是把 CloudBase 的数据库/存储/认证接进 DSH。

## 11. 风险与未验证点

### 11.1 Termux 上装 DSH 可能失败

原生模块（better-sqlite3 之类）在 Android 上可能要现场编译。装了 `python clang make` 后大多能过，但耗时。失败就记录报错再决定。

### 11.2 退路：用 DSH Go 自带的 Ubuntu

旧手机装 DSH Go，它会在 PRoot 里跑完整 Ubuntu（约 1 GB）。在 App 的「终端」里 `apt install openssh-server`、起 sshd，新手机 SSH 进去再起 `dsh web`。共享同一 `$HOME/.dsh`，会话是通的。归 App 管，重置引擎会连带影响，属于"能用但不干净"。

**2026-11-16 实测**：在旧手机上装 DSH Go，本机引擎的安装确实是**一键**的，几分钟就绪。但它只监听 `127.0.0.1`，要当"给别人连的服务器"仍需在 PRoot 里另装 sshd，而且登录令牌每次引擎启动都会变。**所以它没有替代 Termux 方案**，价值在于：

- **备用后端**：Termux 被华为杀掉、或某个包升级装坏了，可以临时切到这台跑（代价是要现配 sshd）。
- **新手机自己的本机引擎**就是这么装的——这也是 App 离线可用的原因。

**别卸载旧手机上的 DSH Go**，留着当备用。

### 11.3 华为后台

四项设置做完仍可能被系统偶尔清掉。表现是"连不上"或"她没说话"。缓解：Termux 常驻通知留着、别手动清后台。

### 11.4 "只连接"连 PC（Work 模式远程）

"只连接"只做 SSH 隧道、不执行远端命令，所以 Windows 的 POSIX 问题不影响。两处未验证：桌面端实例的令牌怎么取；同一会话被桌面端占用时能否写入（`session/writer-held`）。

**验证方法**：PC 上 `dsh web --port 3081 --no-open` 起第二个实例，拿 token，手机"只连接"到 3081。能列会话即通；发消息报 writer-held 则需先关掉桌面端那个会话。

### 11.5 重启后引擎不自启

见 §4.10。MVP 用方案 A。

### 11.6 内容抓取的现实问题

- 反爬：部分站点要 cookie/UA/频率控制，脚本要能失败得干净（明确告诉模型"抓不到"，而不是让它编）。
- 登录态站点：cookie 只放主机本地，禁止进仓库和日志。
- 版权与条款：只为你自己读，不做批量下载和再分发。

### 11.7 CloudBase 的成本与持久化

未核实：云托管持久卷、冷启动、免费额度。**没核实前不要把"她"放到 CloudBase 上。**

### 11.8 记忆系统的两个已知弱点

1. **SQLite FTS5 是否可用**：Termux 的 Python `sqlite3` 模块通常带 FTS5，但个别构建可能不带。装完先跑一句 `python3 -c "import sqlite3;print(sqlite3.connect(':memory:').execute('pragma compile_options').fetchall())"` 看有没有 `ENABLE_FTS5`。没有就退回 `LIKE` 检索，功能不受影响，只是慢一点。
2. **抽取质量决定上限**：模型写候选时容易"过度总结"（把没说过的话说成"他喜欢独处"）。缓解办法是提示词里要求"只写原话能支撑的"，并在周反思里专门检查"这条能指到哪句话"。这类问题不会一次性解决，要跑两周看真实出错率。

## 13. 决策记录：为什么某些东西不在主线

> 这一节是为了防止"过两周又想不起来为什么不用 X"。每个决定都写清楚**什么时候会被推翻**。

### 13.1 CloudBase：不在主线，但保留两个位置

**曾经的想法**：用 CloudBase 当"溟月 Chat 后端"（数据库 + 存储 + 认证），省掉自建服务器。

**为什么撤出主线**：

1. Chat 要能**跑工具** → Chat 必须是一个 DSH 主机（工具在引擎里），不是一个聊天服务。
2. 既然是 DSH 主机，就会话、记忆、人设都在那台机器上，**单事实源，不需要同步后端**。
3. `@cloudbase/dsh-plugin` 是把 CloudBase 后端接进 DSH 的插件，**不能把 DSH 跑在云上**（见 npm 包描述与官方 README）。

**它还有用的两个位置**：

| 用途 | 现在做吗 | 做法 |
|---|---|---|
| **加密备份**（先用 `scp` 回 PC，后切 COS/CloudBase） | ✅ 做，见 [MIGRATION.md](MIGRATION.md) | 每晚导出加密包，保留 14 份 + 月度归档 |
| **只读远程查看**（电脑上看她的日记/记忆） | 暂不做 | 云函数 + 认证给个只读接口 |

**关键决定**：备份的**格式**和迁移的**格式是同一个**（加密 tar + manifest + 恢复脚本）。所以她从旧手机搬到云那天，只是"换一个上传目的地 + 在新机器上跑一遍 restore"。见 [MIGRATION.md](MIGRATION.md)。

**什么时候会真正上云**：当"她掉线"的频率让你烦，或你担心手机坏了。在那之前先做**备份 + 一次迁移演练**——那是真正的保险，云只是目的地之一。

### 13.2 会话双向同步与历史导入：都不做"会话"，只做"记忆"

DSH 没有会话导入接口，会话是引擎私有的 JSONL + 索引。跨端看同一份历史的唯一现成办法是**连同一台主机**。所以：Work 不同步（绑工作区），Chat 走单主机。

历史聊天同理：不导入成会话，导入成 `episodes`/`facts`/`arcs`，见 [IMPORT.md](IMPORT.md)。原文留在 `archive/` 自己翻。

### 13.3 插件：不做（暂时）

"她"是预设 + 文件 + 任务 + skill，不是插件。插件解决的是"界面插槽"，我们没有要加的插槽。要加"她的原生面板"时才回到插件。

### 13.4 桌宠/大肥鱼形象：不做

要它就得走网页插件或改 Flutter，且它只能是"状态指示器"，不承载记忆与对话。与"纯文字的陪伴"目标是两条线。

## 14. 一句话总结

**她不是插件，是你旧手机上的一份配置加一个脚本**：六层分级记忆（核心/情景/语义/前瞻/程序 + 工作记忆）自己整理，每条带出处、能重建、会遗忘；一个内容理解 skill 通吃网页、小说、有字幕的视频。
App 不用改就能连上；电脑端的 DSH 一行都不用动。
真正要动手的只有三件：旧手机装 DSH、写人设与整理任务、写那两个脚本（`mem.py` 和 `fetch.py`）。
剩下的（改名、模式、URL 主机）都是"想更像 Kimi"时才做的可选件。
